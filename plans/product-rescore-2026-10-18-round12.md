# 产品复评 · 十二轮（2026-10-18 21:04）

> 上一轮（十一轮）综合 **9.6**；本轮因 **#43 关联键分桶（scope='key'，traceId/requestId 跨服务关联）落地 + 潜伏 bug 修复** 而调分。

## 核心事件
- 完成 #43 的关联键半边（commit `c817fa7` 双推）：CEP 分桶从「全局 / 线程」二选一扩展为
  **全局 / 线程 / 关联键**三选一。关联键 = 用户正则（须含 1 个捕获组）从原始行抽取
  traceId/requestId，事件按键分桶、链只在桶内匹配——**跨服务/跨文件的分布式调用链首次可关联**。
- **保守降级铁律贯穿**：正则缺捕获组 / 编译失败 / 为空 ⇒ 整组**静默降级 global**（绝不误分桶）；
  正则未命中的事件**不进任何桶**（计 uncovered）——刻意区别于线程的 ∅ 桶，因为关联无键事件
  会制造跨请求假链。
- **顺手修复一个潜伏 bug**：线程分桶的 ∅（无线程）桶此前把 `select=None`（= 全部事件）传给
  `bucket_store`，混合「有/无线程」会话会双计 + 产生跨线程假链；现恒传 `Some("∅")`，
  带回归测试。这使 B 轮刚唤醒的线程分桶能力在混合会话下也真正可信。
- **可观测防静默退化**：`keyStats{totalEvents, withKey, distinctKeys}` 仅在关联键路径真激活时
  产出；指纹规则 `withKey===0`⇒已退化全局、`distinctKeys/withKey>0.8`⇒桶碎裂零链，前端
  `keyHint` 直接渲染提示。降级不再无声。
- UI：分桶开关从二态升级为三态分段控件（🌐 全局 / 🧵 按线程 / 🔑 关联键）+ 条件正则输入框；
  规则导入/导出、Markdown 链标签（「关联键」）、db 模式、模板同步贯通。
- 修复测试基础设施预存缺陷：vitest 默认池在本机无法 spawn worker（`git stash` 干净树同样复现），
  固定 `pool: 'vmForks'` 后 115 个测试恢复可跑——这是后续所有改动的质量网。
- 验证：cargo 120 passed；vitest 115 passed（14 文件）；tsc 0 错；cep-wasm 10/10（含 keyStats
  JSON 往返 + deny_unknown_fields 契约守卫）。
