> 视角：资深产品经理 / 从用户价值出发。

> 顺带把自签 updater 的 CI 失败诊断从"7-12 分钟后一句 base64 错误"升级为"秒级指纹注解"。

## 0. 一句话结论

**第六轮的下一步清单里写着"加载模式透明化：用户仍无法归因为何某能力在此模式不可用"——这轮做了。**

同一份数据进入 logGraph 有两条完全不同的路径：目录加载走 dbMode（原文件即数据库、
rg 直扫、无限上下文流、时间列不可编辑），文件/子集加载走内存模式（全量物化、
上下文档位、时间列可编辑）。此前 UI 没有任何地方告诉用户自己在哪条路径上，
行为差异（详情面板形态、时间列能否编辑、性能特征）完全无法归因。

现在状态栏常驻一枚**加载模式徽标**：hover 看一句话摘要，点击看完整能力边界清单
（4 条 dbMode 边界 / 4 条内存边界 / 3 条 Web 边界）。纯函数 `describeLoadMode`
收口判定与文案，5 条单测锁定三态语义；全量测试 **90/90**（85 → 90，+5）。

综合 **9.1 → 9.2**。UX 维度 **9.0 → 9.1**——这是"用户能理解产品状态"这一类引导的
实质性补齐，而非又一个开关。

## 2. 本轮兑现了什么（代码证据）

### ✅ `src/utils/loadMode.ts` —— 模式判定与文案单一出处
- 纯函数 `describeLoadMode(dbMode, desktop) -> LoadModeInfo`，不依赖 store、无副作用。
- 三态：`db`（数据库模式）/ `memory`（内存模式）/ `web`（内存模式 · Web）；
  每态含 label / summary（hover）/ detailTitle + boundaries（点击 toast 逐行）。
- 边界文案直指真实差异：dbMode "原文件即数据库、直扫磁盘、无限上下文流、
  时间列不可编辑"；内存 "全量物化、上下文档位、时间列可编辑、超大日志建议走目录"；
  Web "浏览器无目录浏览（FSA 限制），大日志会占内存甚至加载失败，要 dbMode 请用桌面版"。

### ✅ Toolbar 状态栏接入（`Toolbar.tsx` + `Toolbar.module.css`）
- `dbMode` selector + `useMemo(describeLoadMode)`，随加载方式实时切换。
- `mode-pill` 按钮渲染在 status-left（文件信息之后）：`data-mode` 属性驱动视觉区分，
  数据库模式以 `--accent` 圆点（外环 `--accent-soft`）标识"在线直扫"，
  其余模式为中性灰点——**不借用 `--anomaly`/`--danger`/`--corr` 数据语义色**。
- hover `title` = summary；点击 `toast.info(detailTitle, boundaries.join('\n'))`。

### ✅ 多行 toast 修复（`ToastHost.module.css`）
- `.detail` 补 `white-space: pre-wrap`——此前换行被折叠，能力边界清单会挤成一段，
  "可读的详解"实际不可读。这是让 P1④ 真正可用的前提修复。

### ✅ 测试
- `src/utils/loadMode.test.ts` 5 测：三态 label 正确、每态 boundaries 非空且含关键差异点、
  dbMode 优先于平台判定（桌面+dbMode → db 而非 memory）、三 label 互不相同。
- 全量 **90/90 通过**；`tsc --noEmit` 零错误。
- 提交 `f49bdf9`，双推 GitCode/GitHub 完成。

## 3. 为什么这是 UX 分而不是"又加个徽标"

判定标准：**它是否消除了一个真实的用户困惑**。

- 困惑是真实的：dbMode 与内存模式是两套引擎、两套详情面板、两种编辑能力，
  而切换入口（打开日志 vs 打开目录）与能力差异（时间列为何点不动）在 UI 上
  相距两个视图，用户此前只能靠猜。
- 消除方式是**告知而非限制**：没有禁用任何能力、没有加教学模式遮罩，
  只是在状态栏常驻一枚可展开的说明——信息密度零成本，归因成本从"猜"降到"点一下"。
- 与既有体系兼容：复用 `toast.*` 反馈约定、CSS 变量体系、status-pill 视觉语言；
  文案全部收敛在纯函数里，后续改口径只动一处。
