### 工程分为什么又降了 0.1（9.3 → 9.2）

不是退步，是继续**记账**：跨行 filter 的 `splitSubConditions` / `aggregateSubHits`
现在两端各有一份实现（引擎 `session.rs` ↔ 前端 `FilterEngine.ts` + `dbStore.ts`），
同步点又多一处。这与上一轮记 CEP 双实现是同一笔账的不同条目——
**能力每下沉一次，同步面就扩大一圈**。消掉双实现仍是唯一解，
且随着每次下沉，它的优先级只升不降。

### 价值不在分数，在「从只能看，到能改」

四项里真正改变用户行为的是解释器与异常分级，它们共同解决同一件事：
**CEP 之前只能告诉用户「没有/有」，现在能告诉用户「为什么/哪里」**。

- 异常分级：33 万条 → N 段，且段的大小本身是信号（1 段 500 条的密集爆发 ≠
  500 段零散 1 条）。
- 解释器：零链 → 「间隔超限：最近的一对也隔了 8 秒，边设定窗口是 1 秒」。
  给具体数字，不说空话。

两者都是**纯函数、不碰匹配语义**——只解释结果，永不改变结果。这是它们能被
放心加进来的前提。

### 待用户操作（否则 updater 不生效）

minisign 私钥须加进 GitHub Secrets `TAURI_SIGNING_PRIVATE_KEY`，
否则 CI 签不了名、`latest.json` 不会产出，**更新通道不生效**。
私钥丢了就无法再签名，更新通道永久失效——请妥善保存。

### 下一步（第四轮之后）

1. **消 CEP 双实现**（仍是第一优先级，且优先级在升高）。可先把跨行聚合统一到
   引擎侧，再逐步让 UI 全量走引擎。
2. 跨行 filter 的 `gapMs` / 异常分级的阈值目前是常量，可考虑按日志密度自适应。
3. 代码签名证书：**不做**（要花钱，与代码质量无关）。代价是首次放行，已写入
   release notes，可接受。

### ✅ thread 启发式的脆弱性被诚实暴露（`2efa401`）

实测 9 种常见日志格式**只有 1 种**能解析出 thread（log4j2 线程在前的写法）；
Spring Boot / Logback 两种主流 Java 写法、nginx / syslog / Python logging 全部为 None。

处置是**可观测而非自适应**：`SeqResult.threadStats`（totalEvents/withThread/distinctThreads）
不论 scope 都回传；覆盖率为 0 时 UI 直说"此时等同全局，链会跨线程串出伪链"。
**明确禁止**靠"放宽锚定、到处找方括号"提高覆盖率——那会把漏解析（退化成全局，保守可用）
换成更坏的误抓（流被拆碎 ⇒ 零链 = 全部漏报）。理由写进契约 §3.13，防止后人反向优化。

## 5. 方法论反思：评审必须验证代码，不能只读文档

二轮把 **P1⑥ 模板库**记为"❌ 未动"，但核实提交时间戳后发现：

```
1f7f008  14:08:38  发首个 release + 二轮复评文档
70b3f07  14:08:46  CEP 规则模板库与引导式创建（P1⑥）
51152a2  14:08:54  CEP 引擎下沉 opt 边能力
```

**复评文档与模板库代码是同一批次提交的**——评审写下"未动"时，代码就在库里。

教训：评审若以文档/commit 标题为依据，会把已兑现的记为未兑现（低估），也可能把
"写了但没接线"的记为已完成（高估）。本轮对每一项都追到代码证据：
- 模板库 → 查 `CommandPalette.tsx` 是否真有入口（有，`RULE_TEMPLATES.forEach`）
- release → 查匿名 API `/releases` + 公开页面 + `releaseDraft` 配置

### 附：本轮我自己犯的一处措辞失真（值得记取）

我把"产物对外不可见"写成了"用户一个都下载不到"，听上去像**产物没构建出来**。
用户随即反驳"release 页面不是有安装包了吗"——他登录着、看得到草稿里的 7 个产物。

同一个事实，两个视角给出相反结论：

| 视角 | 所见 |
|---|---|
| 匿名 API | 0 个 release |
| owner 登录网页 | 2 个 release，各 7 个产物 |
| 事实 | 产物早已构建完成，卡在**草稿**状态 |

两条教训：
1. **对外可见性必须用匿名视角验证**，登录态页面会骗人（这是发现问题的前提）；
2. **但表述时要区分"产物不存在"与"产物不可见"**——前者是事故（要重做构建），
   后者是配置问题（改一行）。评审把后者说成前者，会让团队在错误的方向上投入。
   本轮真实成本是：改 1 行 `releaseDraft`，而不是重做三平台构建。
- 更新通道 → 查 `tauri.conf.json` 有无 updater（无）

**"提交过"≠"已交付"，"跑通 CI"≠"用户拿得到"。** 这三处差别正是本轮分数的关键。
